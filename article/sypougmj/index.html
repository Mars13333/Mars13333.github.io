石器时代

现在比如说来了一个日常迭代的新需求，需要新增一个图书管理模块。

大家可以闭眼两秒，回想一下在没有 AI 的“石器时代”，接下一个简单的 CRUD 需求，我们的标准动作是怎么样的：

  1. 后端：漫长的“仪式感”

  • 先去数据库建表，然后对着表字段，一个一个在 Java 里敲出 Entity。

  • 手写 DTO、VO，再写一套像复读机一样的 Service 和 ServiceImpl。

  • 接着是 Controller，还要手动配置分页插件，测试一下 Swagger 接口动不动得了。

  1. 前端：精细的“像素级”搬砖

  • 看着 UI 稿（甚至没有 UI），在 Vue 里一行行写 el-form-item。

  • 关键是字段得对齐：后端叫 book_status，前端字段叫 status 还是 bookStatus？

  • 复制一份 Axios 请求模板，改改 URL，祈祷别拼错单词。

  1. 联调：名为“对齐”的拉锯战

  • “诶？你接口字段名怎么变了？”

  • “跨域了，你后端加个注解啊！”

  • “这个时间格式不对，你转个 ISO 字符串给我。”

  1. 反复：无穷无尽的微调
  • 数据库多加一个字段，意味着你要改：SQL -> Entity -> DTO -> Service -> Controller -> API 封装 -> 前端表单。

结论： 哪怕是一个只有 5 张表的增删改查，从建表到跑通联调，一个熟练工没两三个小时也下不来，更别提中间还要喝三杯咖啡来抵御这种重复劳动的枯燥。

写在最后

看着终端里 Claude Code 飞速跳动的代码行，我坐在椅子上，心里其实挺复杂的。

从“石器时代”的一行行手敲，到现在的 5 分钟速通，CRUD 的门槛正在以一种近乎蛮横的方式坍塌。这件事儿，咱们得分两面看：

先说忧。 以前能写一手规范的增删改查、能熟练搞定前后端联调，那是程序员立身的本事。现在呢？AI 像一个不知疲倦的高级劳动力，只要你的“指令”够清晰，它能比你写得更稳、更快。有些人看到这种新鲜事物，第一反应是拒绝、是防御。但我得说句掏心窝子的话：在这个快节奏的时代，不保持持续学习，真的会被淘汰。 傲慢和偏见，是新技术浪潮里最重的枷锁。

再说喜（也就是大家最关心的）。 效率提升了，意味着我们的生产力被无限放大了。说个俗点的，如果我有稳定的渠道，手里有接不完的外包项目，以前一个人一个月只能啃一个，现在配合 Claude Code，我一个月能撸一打！这哪是代码生成器啊，这分明是自动印钞机。（哈哈哈哈，允许我先白日梦一下）

一句话总结： 不要去对抗趋势，要去拥抱变化。AI 夺不走你的工作，只有那个“比你更会用 AI 的人”才会。

把枯燥的重复劳动交给机器，把时间留给更有价值的思考（或者留给生活和家人）。毕竟，我们学编程是为了改变世界，而不是为了当一辈子的“CRUD 搬砖工”。
